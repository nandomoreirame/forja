Contributing

Contributions to Forja are welcome. This section covers everything you need to get started: prerequisites, setting up a development environment, our commit conventions, and how to submit a pull request.

Prerequisites

Before you begin, make sure the following tools are installed:

ToolMinimum versionNotes
Node.js22.xManaged via mise or nvm
pnpm9.xPackage manager for the monorepo
Git2.30+Required for branching and commits

Platform-specific dependencies

Native addons (node-pty) require a C++ build toolchain.

Linux

macOS

Windows

Install Visual Studio Build Tools with the Desktop development with C++ workload. Python 3 must also be available in PATH.

Fork and branch workflow

Forja uses Trunk-Based Development: main is the single integration branch. All changes go through short-lived feature or fix branches.

Keep branches short-lived and focused on a single concern. Rebase on main before opening a PR if your branch has diverged.

Commit conventions

Forja follows Conventional Commits. Every commit message must begin with a type and optional scope:

Types

TypeWhen to use
featA new feature or user-visible capability
fixA bug fix
refactorCode restructuring with no behavior change
testAdding or updating tests only
docsDocumentation changes only
choreBuild scripts, dependency updates, tooling
perfPerformance improvements
styleFormatting, whitespace, lint — no logic change
ciCI/CD configuration changes

Scopes

Use the package or area of the codebase your change touches:

ScopeArea
frontendReact frontend (apps/desktop/frontend/)
electronElectron main process (apps/desktop/electron/)
desktopDesktop app in general (both layers)
siteMarketing site (apps/site/)
docsDocumentation site (apps/docs/)
mobileMobile app (apps/mobile/)
sharedShared package (packages/shared/)
configelectron/config.ts / electron-store
settingselectron/user-settings.ts
terminalPTY / xterm.js layer

Pull request checklist

Before submitting a PR, make sure:

  • All existing tests pass: pnpm test
  • New behavior is covered by tests (TDD preferred)
  • TypeScript compiles without errors: pnpm build
  • Commit messages follow Conventional Commits
  • The PR description explains the why, not just the what

Getting help

If you are unsure about an approach or want feedback before investing significant time, open a GitHub Discussion or draft PR first. We are happy to review early.
